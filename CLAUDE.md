## GDScript conventions

- Use static type hints everywhere: typed variables (`var speed: float = 5.0`), typed function params and return types (`func move(delta: float) -> void:`), and typed arrays (`Array[Node]`). Prefer `:=` inferred typing only when the right-hand type is obvious.
- Prefer `@onready var node: Type = %NodeName` (unique-name access) over `$Path` for node references.
- Use `class_name` for reusable types so they resolve as static types elsewhere.
- `gdscript/warnings/untyped_declaration` is enabled in `project.godot` — keep new code warning-clean.

## Architecture

### `fluid/` — GPU fluid simulation

A GPGPU ping-pong simulation done entirely with `canvas_item` shaders (no compute shaders):

- **State packing** — the whole fluid field is one RGBA texture: `R,G` = velocity (signed, stored as `x*0.5+0.5`), `B` = dye, `A` = pressure (signed, same encoding). Any shader reading the field must `decode()`; `fluid_sim.gdshader` and `fluid_display.gdshader` must keep the same packing.
- **Ping-pong** — two `SubViewport`s (`SimA`/`SimB`), each with a full-rect `ColorRect` sharing one `ShaderMaterial`. `fluid_sim.gd::_process()` sets `u_prev` to the source viewport's texture, flips the destination viewport to `UPDATE_ONCE` for exactly one step, points the display material at the fresh result, then swaps. Viewports are `UPDATE_DISABLED` + `CLEAR_MODE_NEVER` otherwise.
- **Startup** — `_reset_frames` forces the sim shader to write an encoded-zero state for the first few frames, because `SubViewport` render targets start undefined and `decode()` of zero is not zero velocity.
- **Forces** — left-drag in `_input()` writes `_force_pos`/`_force_dir` (normalized screen space, Y-down to match shader `UV`); `_force_dir` decays each frame.
- The solver is a single-pass approximation (one Jacobi iteration for diffusion and pressure, fused projection) ported from external WebGL shaders — plausible motion, not a physically accurate or divergence-free solve. `noise.gdshaderinc` (value/curl noise) is included but currently unused by the solver.

`use_hdr_2d = true` on the SubViewports gives `RGBA16F` precision; the `x*0.5+0.5` encoding is what actually keeps signed values safe, so keep it even though the target is float.

## Notes

- Headless (`godot --headless`) uses a dummy renderer: it validates scene loading and GDScript parsing but **not** shader compilation or visual output. Shader changes must be verified with a real GPU run (`godot` with a display).

- `.godot/` is generated by the engine and gitignored — never edit it; it is recreated on editor open/import.
- Scene (`.tscn`) and resource (`.tres`) files are text — hand-editing is possible but regenerating UIDs and `ext_resource` IDs by hand is error-prone; prefer the editor for structural changes.
